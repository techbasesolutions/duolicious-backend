# Ahavah Launch Implementation Plan

> **For agentic workers:** Implement task-by-task. Destructive/outward tasks (8, 9, 10) are GATED — STOP and get explicit user approval before running them. Steps use `- [ ]`.

**Goal:** Launch Ahavah — purge test accounts, retire the preview host, and email all 53 waitlist registrants a magic link that logs them in, pre-fills their account from their waitlist answers, and drops them into onboarding to finish.

**Architecture:** A signed `claim` token (existing HMAC unsubscribe-token system, new scope) → `POST /claim` upserts an `onboardee` pre-filled from `waitlist_signup.answers` and mints a signed-in session (admin "log in as user" pattern) → FE `/claim/[token]` stores the session and routes into the existing onboarding wizard. Purge uses `person` FK CASCADE. Email reuses the brand shell + a dry-run send script.

**Tech Stack:** Flask + sync psycopg + Postgres (ahavah-api); Next 16 + React 19 + Tailwind v4 (ahavah-web); Vercel; DO droplet + Spaces.

**Environment note:** No local Python — backend "tests" are the e2e claim check run in-container post-deploy, plus a 401/health route check. FE verified via `tsc`/`eslint` + rendered screenshot.

## Task 2: `service/claim` — onboardee upsert + session mint (CORE)

**Files:** Create `service/claim/__init__.py`

**Read first (to write exact SQL — do NOT fabricate):**
- `service/person/sql/__init__.py` — the `onboardee` INSERT in `Q_MAYBE_SIGN_IN` (~line 370) for the exact column list + the `gender.name → gender_id` lookup used by the PATCH `/onboardee-info` handler (`service/person/__init__.py:492-675`), and the `location` → `coordinates` lookup. Also `Q_INSERT_DUO_SESSION` (`service/person/sql/__init__.py:245`) for the session insert shape.
- `service/location/__init__.py` — `get_country_location(cc)` (built earlier) for country→representative location/coordinates.
- `service/api/admin/users_action_routes.py:285` — `secrets.token_hex(64)` + `sha512` session-mint reference.

**Contract:**
```python
def claim(tx, token: str) -> dict | None:
    """Resolve a claim token to a signed-in session, creating/pre-filling an
    onboardee from the waitlist answers on first use. Returns
    {"session_token": <128-hex>, "onboarded": bool} or None if the token is
    invalid. Idempotent: an existing person for the email is just re-logged-in
    (no duplicate onboardee)."""
```

- [ ] **Step 1:** `parse_token(token)` (from `service.unsubscribe`) → `(scope, email)`; return `None` if invalid or `scope != "claim"`.
- [ ] **Step 2:** Look up whether a `person` already exists for `normalized_email`. If yes → skip onboardee creation, mint a session with `person_id=<that id>`, return `{session_token, onboarded: True}`.
- [ ] **Step 3:** Else load `waitlist_signup.answers` (via `service.waitlist.get(tx, email)`). Build the pre-fill: `gender_id` from `answers.sex` (gender.name lookup; omit if no match), `coordinates` from `get_country_location(answers.country)` (omit if unresolvable), `ahavah_extra` = JSON of `{k: answers[k]}` for k in `{assembly, intent, family, relocate_willing}` present.
- [ ] **Step 4:** UPSERT the `onboardee` row (email + normalized_email + the pre-fill columns), matching the column types from the read above. Leave name/DOB/photos NULL.
- [ ] **Step 5:** Mint session: `token = secrets.token_hex(64)`; `hash = sha512(token)`; INSERT `duo_session (session_token_hash, person_id=NULL, email, signed_in=TRUE, otp=<placeholder>, ...)`. Return `{session_token: token, onboarded: False}`.
- [ ] **Step 6:** Commit: `feat(claim): onboardee upsert + session mint from waitlist answers`.

**Verify-at-build:** confirm `answers.sex` strings match `gender.name`, and `answers.country` is ISO2 as `get_country_location` expects. If a mismatch, normalize in this module (a small map) — the Task 4 e2e test surfaces it.

## Task 3: Wire `POST /claim`

**Files:** Modify `service/api/__init__.py` (near the other public POST routes; this one is UNAUTHENTICATED — the token is the auth).

- [ ] **Step 1:** Add route:
```python
from service.claim import claim as _claim

@app.post('/claim')   # match the app's actual route-decorator convention in this file
def post_claim():
    token = (request.get_json(silent=True) or {}).get('token')
    if not token:
        return {'error': 'missing_token'}, 400
    with api_tx() as tx:
        result = _claim(tx, token)
    if result is None:
        return {'error': 'invalid_token'}, 400
    return result
```
(Confirm the unauthenticated-route decorator pattern used by `/check-otp` / `/request-otp` and match it — do not use `@aget`/`@apost` if those force auth.)
